# FuhGlGraphics — Procedural Creature Generation (G32) design

Status: **design agreed, implementation in `procedural/creaturegen.{hpp,cpp}`.** Language of
this document: English (docs at this level are English-only, see [README.md](README.md)).
The *algorithms* below are deliberately **language- and engine-agnostic**: no code, no
frameworks — only mathematics, data structures and step-by-step procedures.

## 0. Scope and relation to existing modules

The library already has the low-level building blocks; G32 composes them into one pipeline:

| Pipeline stage | Existing module | G32 adds |
|---|---|---|
| Seeded 3D noise (simplex, fBm) | G24 `procedural/noise.hpp` | Worley (cellular) detail, reaction–diffusion pattern |
| Marching cubes meshing | G25 `procedural/marching_cubes.hpp` | per-vertex curvature + material masks |
| SDF primitives + smooth-min | G29 `procedural/sdf.hpp` | three anatomical layers (bone/muscle/skin) + gravity sag |
| Skeleton graph → SDF → mesh → baked maps | G30 `procedural/creature.hpp` | allometric blueprint generator, bilateral symmetry, IK locomotion |

End-to-end pipeline (each stage is a pure function `stage(input) -> output`, deterministic
per seed, no GPU needed for generation):

```
ecological inputs ──▶ 1. blueprint + skeleton ──▶ 2. layered SDF ──▶ 3. surface + masks
      ──▶ 4. UV-free material bake ──▶ 5. rig + gait pose (per frame)
```

## 1. Evolutionary blueprints & allometry (proportions)

### 1.1 Input vector

A creature is fully described by a small ecological input vector `E`:

- `M` — body mass [kg]
- `locomotion` ∈ {quadruped, biped, serpentine, …}
- `diet` ∈ {herbivore, carnivore, omnivore}
- `climate` ∈ {polar, temperate, tropical, arid}

plus a seed for all stochastic choices.

### 1.2 Allometric rule system

A rule-based parameter generator maps `E` to a coupled proportion vector `B`
(body length, body radius, leg length, bone radius, neck length, head size, tail length,
eye size, eye position, ear size, subcutaneous fat thickness, fur density, horn presence).
The rules are **allometric scaling laws** — power laws `y = a · M^b` with empirical
exponents — plus **coupling constraints** between parameters:

- Linear body dimensions scale sub-isometrically: body length `L ∝ M^0.27`,
  body radius `R ∝ M^0.29` (isometry would be `M^(1/3)`; real animals are relatively
  slimmer at large mass).
- **Bone thickness vs. mass** (Galileo's law): to keep bone stress constant under body
  weight, cross-sectional area must grow ~linearly with mass, so bone radius
  `r_bone ∝ M^0.36` (empirical exponent; isometry would give `M^(1/3)`). Leg length
  `L_leg ∝ M^0.25`.
- **Eye position, predator vs. prey**: predators get frontally placed, forward-facing eyes
  with wide binocular overlap (`eyeForward ≈ 0.8…0.95` of head width, small interocular
  angle); prey get laterally placed eyes (`eyeForward ≈ 0.05…0.2`) with a near-panoramic
  field of view. Eye size scales with head size: `r_eye ∝ headSize · M^0.05`.
- **Climate rules** (Bergmann / Allen): cold climates → larger, more compact body
  (`R` multiplied by ~1.15), thicker subcutaneous fat layer, high fur density, small ears;
  hot/arid climates → slimmer body, thin fat, large ears (heat dissipation).
- **Locomotion**: quadruped → 2 leg pairs, horizontal torso; biped → 1 leg pair, upright
  torso (vertical ellipsoid stretch); serpentine → 0 leg pairs, elongated torso, long tail.

Algorithm (step by step):

1. Normalize `M` to a reference range (log-scale) to keep power laws numerically stable.
2. Evaluate the power-law rules for the *size-driven* parameters (body, bones, legs).
3. Evaluate the *categorical* rules (diet → eye position; climate → fat/fur/ears;
   locomotion → leg count, torso orientation, tail length) as a small decision table.
4. Apply coupling constraints: e.g. `headSize ≤ 0.35 · neckLength`, `tailLength` limited so
   that total length stays consistent with `L`; horns only for large herbivores/omnivores.
5. Emit `B` and the seed.

### 1.3 Hierarchical skeleton graph

Data structure: a **rooted tree (graph)** of joints. Each node stores:
`id, name, parentId, localOffset (translation relative to parent), radius, ellipsoidScale,
bodyPart, blendFactor`. World position of a node = accumulated parent offsets (forward
kinematics along the tree).

- **Bilateral symmetry**: the body is symmetric about the sagittal plane (x → −x). Only the
  right side is parameterized; left-side nodes are generated by mirroring the offset's
  x-component. Spine nodes (torso, neck, head, tail) lie on the plane (x = 0).
- **Controlled micro-asymmetry**: after mirroring, each node offset is jittered by a small
  seeded noise term `ε · n(seed, nodeId)` with `ε ≈ 1–3 %` of the local segment length —
  large enough to look organic, small enough to keep the symmetry readable.

Algorithm: generate spine chain (torso → neck → head → jaw, plus tail chain), then for each
leg pair generate right-side chain (shoulder/hip → elbow/knee → foot) and mirror it; add
horns/eyes as head children (horns mirrored, eyes mirrored with eyeForward placement).

## 2. Anatomically layered geometry generation (SDF)

### 2.0 SDF basics

A signed distance field `d(p)` is negative inside the body, positive outside, `|∇d| ≈ 1`
near the surface; the surface is the iso-set `d(p) = 0`. Primitives used: sphere, ellipsoid,
tapered capsule (segment `a→b`, radius lerp `ra→rb`), each with an analytic distance.
Fields are combined with the **polynomial smooth minimum**

```
smin(a, b, k) = min(a, b) + smooth polynomial correction, active only within radius k
```

`k` is the *blend radius*: small `k` → hard union (sharp edges), large `k` → soft, organic
fusion.

### 2.1 Three anatomical layers

The skeleton's primitives are partitioned into three layers, each combined with its own
blend radius:

1. **Bone anchor layer** — small ellipsoids at the joints (radius ≈ 0.55 · muscle radius),
   blend radius `k_bone` **small** (≈ 0.02 · bodyRadius). Produces hard, sharp features:
   joints, and — with `k ≈ 0` (plain min) — **keratin structures** (horns, claws, teeth,
   hooves) which must stay sharp.
2. **Muscle strand layer** — one tapered capsule per skeleton link, with a **fusiform
   (spindle) radius profile** along the segment:
   `r(t) = lerp(ra, rb, t) · (0.55 + 0.45 · sin(π·t)^β)`, `β ≈ 0.7` — thin at the tendons,
   thick at the muscle belly. Blend radius `k_muscle` **medium** (≈ 0.08 · bodyRadius).
3. **Skin/fat overlay layer** — all primitives at full radius plus the fat thickness,
   blend radius `k_skin` **large** (≈ 0.25 · bodyRadius), plus a **gravity sag** term that
   pulls the underside down, decaying with height above the ground:

   ```
   d_skin(p) = smin_all(p, k_skin) − sagAmp · exp(−p.y / sagHeight) · underweight(p)
   ```

   where `underweight(p)` is a smooth mask that is 1 on the belly and 0 on the back
   (e.g. based on the surface normal's y-component or the position relative to the torso
   midline).

Final field before detail:

```
d_layered(p) = smin( d_bone(p), smin(d_muscle(p), d_skin(p), k_muscle), k_skin )
```

### 2.2 Surface detail in the field

Fine details are modulated **directly into the distance field** (so meshing picks them up
as real geometry, and normals stay consistent):

```
d(p) = d_layered(p) + A_simplex · fBm_simplex(f_detail · p, octaves)
                    − A_scale  · (1 − F1_worley(f_scale · p))^2
```

- Simplex fBm (2–3 octaves): low-frequency wrinkles and folds.
- Worley/cellular noise `F1` (distance to nearest feature point of a jittered lattice):
  `1 − F1` is a cone per cell; squaring it gives rounded **scales**; scaling the input
  anisotropically (stretched along the body axis) turns scales into **ridges/stripes**;
  pores are small negative Worley bumps at a higher frequency.

## 3. Surface extraction & geometry masks

### 3.1 Volume → closed polygon mesh

1. Compute the bounding box of all primitives (broadphase AABBs) plus a margin of
   `k_skin + max detail amplitude`.
2. Sample `d(p)` on a uniform `N³` lattice over the box (index order x + nx·(y + ny·z)).
3. Run **marching cubes** at isolevel 0 (classic 33-case table): for each cell with sign
   changes, emit triangles; place vertices on crossing edges by **linear interpolation** of
   the field values (this preserves sharp features because the field itself is exact there —
   keratin prims use `k ≈ 0`, so their edges stay crisp).
4. Weld shared vertices → indexed mesh. Optionally split into chunks (shared boundary
   layers) for large creatures, so seams coincide exactly.

### 3.2 Analytic normals

At each surface vertex `p`:

```
n(p) = − normalize( ∇d(p) ),   ∇d via central differences:  (∂d/∂x, ∂d/∂y, ∂d/∂z),
                                ∂d/∂x ≈ (d(p+h·ex) − d(p−h·ex)) / (2h)
```

with `h` ≈ half a voxel size. Because `d` is evaluated analytically (not from the mesh),
normals are smooth and independent of tessellation.

### 3.3 Curvature mask

Local surface curvature from the field's second derivatives:

```
H(p) ≈ ½ · ∇²d(p) / |∇d(p)|        (mean curvature at the surface, sign included)
∇²d(p) ≈ (Σ d(p ± h·ei) − 6·d(p)) / h²   (discrete Laplacian)
```

Sign convention: `H < 0` concave (creases, grooves between muscles), `H > 0` convex
(ridges, knuckles). Stored as a **per-vertex mask** `curv(v) = H(p_v)` and used for
shading (creases darken) and for texturing (see §4).

### 3.4 Material mask

Each vertex also gets a **material id** from the nearest primitive's `bodyPart`:
`0 = skin/fur`, `1 = keratin` (horn/claw/hoof/jaw), `2 = eye`. Computed by a nearest-prim
query (broadphase AABB first, then exact primitive distance).

## 4. Biologically motivated texturing & materiality (UV-free)

### 4.0 UV-free object-space projection

No UV unwrap is used. Every shading quantity is a function of the **3D object-space point
`p`** (and the analytic normal `n(p)`). For baking to a 2D texture, a **cylindrical
projection around the body axis (+Z)** is used: `u = atan2(p.y, p.x) / 2π + ½` (seamless —
the angle wraps the full circle), `v = (p.z − z_min) / (z_max − z_min)`. The surface point of
a texel is recovered by casting a ray from the body axis outward and bisecting on the SDF,
so all noise is evaluated at the *true 3D* surface point — the texture is seamless by
construction. (For non-cylindrical parts, triplanar projection — three axis-aligned
projections blended by `|n·axis|` weights — is the fallback.)

### 4.1 Reaction–diffusion (Turing) camouflage patterns

Organic spot/stripe patterns are **Turing patterns**: two morphogens `U, V` on the surface
evolving by reaction–diffusion

```
∂U/∂t = D_U ∇²U − U·V² + F·(1 − U)
∂V/∂t = D_V ∇²V + U·V² − (F + k)·V          (Gray–Scott model)
```

Discretized on the cylindrical `(u, v)` grid (periodic in `u`, Neumann in `v`) with explicit
Euler steps and a 5-point Laplacian:

1. Initialize `U = 1`, `V = 0` everywhere, plus a small seeded blob of `V` (a few cells).
2. Iterate `T` steps (a few hundred): `lap` from the 4-neighbour stencil (wrapping `u`),
   update `U, V`, clamp to `[0, 1]`.
3. **Anisotropy → stripes vs. spots**: scale the `v` coordinate of the Laplacian stencil by
   `a ≥ 1`; high `a` stretches the cells along the body axis, producing stripes; `a = 1`
   gives spots/labyrinth.
4. Pattern mask: `m(p) = smoothstep(θ − s, θ + s, V(p))` with threshold `θ` and softness `s`.

The result `m(p) ∈ [0,1]` blends two palette colors (e.g. dark spots on a lighter base):
`albedoPattern(p) = mix(base, accent, m(p))`.

### 4.2 Biological color rules

- **Countershading**: brightness depends on the surface's up/down orientation. Let
  `ny = (p.y − y_mid) / r(p)` ∈ [−1, 1] be the normalized height in the body cross-section
  (−1 belly, +1 back). Then
  `color = mix(ventralColor, dorsalColor, smoothstep(−0.1, 0.35, ny))`
  — dark back, light belly (also expressible via `n·up` for arbitrary poses).
- **Curvature darkening in folds**: multiply by `1 − c_dark · max(0, −H(p))` using the
  curvature mask from §3.3 — creases and scale grooves darken automatically.
- **Material transitions**: where the material mask is keratin, override with a pale,
  low-saturation color and lower roughness (hard, smooth horn/claw vs. skin/fur); the accent
  color is applied only to small masked regions (eyes, combs — a few % of the surface); fur
  is expressed as high-frequency bump only (no color change) with density from the blueprint.
- Low-frequency fBm variation multiplies everything to break up uniformity.

### 4.3 Ecology → color mapper (biological camouflage rules)

Animal colors follow strict evolutionary rules, not chance. The mapper takes the ecological
input (`biome, mass, predator/prey, day/night, toxic`) and derives the palette:

- **Background matching**: the base color is the dominant color of the spawn biome
  (ochre/beige desert, moss-green/bark-brown forest, white/blue-grey tundra, blue-grey ocean).
- **Gloger's rule** (humidity × temperature): the warmer *and* more humid the biome, the
  darker and more saturated the pigments (melanin rise in tropical forests); dry, cold
  regions get lighter, paler colors.
- **Aposematism vs. camouflage**: large animals / herbivores get muted, desaturated earth
  tones (low saturation, medium contrast); small toxic/defended animals (`toxic = true`,
  small mass) invert the rule — maximal saturation and hard contrast (black + yellow/red).
- **Nocturnal** (`nocturnal = true`): shift into the cool spectrum (blue-grey, deep black,
  violet tint) with clearly lower brightness.

### 4.4 Gray–Scott presets & Murray's-law coupling

The same reaction–diffusion algorithm produces biologically exact patterns from just the
feed/kill rates `(f, k)`:

| f | k | pattern | like |
|---|---|---|---|
| 0.055 | 0.062 | coral / labyrinth | pufferfish |
| 0.035 | 0.065 | spots | leopard / cheetah |
| 0.025 | 0.050 | stripes | zebra / tiger |
| 0.014 | 0.054 | networks | giraffe |

**Murray's law** (pattern depends on body-part thickness): the pattern domain is sampled
faster along the body axis where the local part radius is small — a thin tail automatically
gets rings (raccoon), the wide torso keeps spots. Feature size also scales with body mass
(bigger animal → larger, rarer features).

### 4.5 Environment → pattern rules

- Dense vegetation (jungle/forest, leaf-shadow dappling) → spots/rosettes to dissolve the
  silhouette in the light/shadow play.
- Tall grass / reeds (savanna/steppe) → pattern coordinates stretched vertically → stripes.
- Open terrain (desert/ocean/tundra, no sharp shadows) → no hard pattern; soft
  countershading + fine grain only.
- Rocky mountains (sharp rock edges) → Voronoi/cell pattern with hard color contrast
  (disruptive coloration).

### 4.6 Harmonic palettes in HSV

All palette math happens in HSV (never raw RGB), with fixed harmony rules so colors never
look artificially bright:

1. **Base**: from the biome (background matching + Gloger + aposematism/nocturnal shifts).
2. **Belly**: same/slightly warmer hue (+5°), saturation halved, value ≈ 0.8.
3. **Pattern**: hue +10…20° (analogous), slightly higher saturation, value 0.15 (dark) or
   0.85 (light variant).
4. **Accent** (eyes, combs, display traits): complementary hue (+180°), high saturation,
   limited to ≤ 5–10 % of the body surface via the vertex material mask.

Material gloss follows humidity: wet (amphibians/reptiles) → glossy low roughness, dry
fur/desert → matte.

Output: baked RGBA8 **albedo** and tangent-space **normal map** (from a height field =
fBm + Worley groove term, gradient via central differences on the `(u,v)` grid, wrapping
in `u`), plus the material/pattern masks — all in object space, hence seamless.

## 5. Procedural locomotion & kinematics

### 5.1 Rig

The skeleton tree is the rig. A **pose** is a vector of world-space joint positions
`J[i]`, one per node. Rest pose = accumulated offsets (FK). Skinning of the mesh to the rig
uses per-vertex bone weights derived from the distance to the nearest prim (the same
query as the material mask) — smooth weights via smooth-min over the two nearest bones.

### 5.2 Inverse kinematics for arbitrary limb lengths & terrain

Legs are 3-node chains (hip/shoulder → knee/elbow → foot). For each chain the **analytic
two-bone IK** is used (closed form, no iteration, stable with joint limits):

1. Given root `r`, target `t`, segment lengths `l1, l2`:
   `d = clamp(|t − r|, |l1 − l2| + ε, l1 + l2 − ε)` (clamp handles unreachable targets).
2. Cosine rule: `cos α = (l1² + d² − l2²) / (2 · l1 · d)` → bend angle at the root joint.
3. Mid joint (knee/elbow) lies in the plane spanned by `(t − r)` and the chain's bend axis
   (for legs: the outward normal of the body, e.g. +x for the right leg):
   `mid = r + l1 · (normalize(t − r) rotated by α around the bend axis)`.

**Terrain adaptation**: the foothold target is `t = restFoot + moveDir · stride · cos(φ)`,
with `t.y = terrainHeight(t.x, t.z) + lift`, where the swing lift is
`lift = liftHeight · max(0, sin(φ))` and `φ = 2π · cycleHz · t_time + phase_leg`.
The terrain is queried as a heightfield `y(x, z)` (raycast against a mesh as fallback).
Because IK is solved per frame against the actual terrain sample, **any limb length and any
terrain unevenness** are handled.

### 5.3 Gait

A gait = per-leg phase offsets `phase_leg` (fractions of the cycle). E.g. lateral-sequence
walk for a quadruped (left hind 0, left front 0.25, right hind 0.5, right front 0.75);
trot = diagonal pairs {0, 0.5, 0.5, 0}; gallop adds a spinal flexion component. The gait
parameters (cycle frequency, stride length, lift) scale with body mass
(`cycleHz ∝ M^−0.18`, `stride ∝ M^0.3`).

### 5.4 Secondary motion

- **Traveling wave along spine and tail**: after the leg IK, each spine/tail node `i` at
  arc-length `s_i` along the chain gets a lateral offset
  `Δx_i = A · envelope(i) · sin(2π · (s_i / λ − f · t))`,
  where the envelope grows from 0 at the shoulders to `A` at the tail tip
  (e.g. `envelope = (s_i / s_total)^1.5`), `λ` = wave length, `f` = wave frequency tied to
  the gait cycle. This produces the lateral undulation of swimming/crawling and the
  subtle sway of walking.
- **Breathing**: thorax nodes (torso, neck base) are displaced radially outward from the
  body axis by `Δ = breathAmp · sin(2π · breathHz · t)`, with `breathAmp ≈ 1–2 %` of the
  torso radius and `breathHz` scaling inversely with mass (`∝ M^−0.17`, Kleiber).

### 5.5 Per-frame evaluation order

1. Query terrain under the root → set root height (body floats at `legLength` above ground).
2. Compute foothold targets per leg from gait phase; solve two-bone IK per leg chain.
3. Apply the spine/tail traveling wave on top of the FK pose.
4. Apply the breathing displacement on the thorax.
5. Forward-kinematics pass over the tree → world joint positions `J[i]` → skin the mesh
   (or re-evaluate the SDF if the geometry itself must breathe).

## 6. Data-structure summary

| Structure | Content |
|---|---|
| `Ecology` | mass, locomotion, diet, climate, biome, nocturnal, toxic, seed |
| `BiomeInfo` | biome base color, humidity, temperature, vegetation, structure flags |
| `Blueprint` | coupled proportion vector `B` (allometry output) |
| `SkeletonNode` / `Skeleton` | joint tree: parent, local offset, radius, ellipsoid, body part, blend |
| `Anatomy` | layer blend radii, sag, detail amplitudes/frequencies, seed |
| `SurfaceMasks` | mesh + per-vertex normal, curvature, material id |
| `Palette` | dorsal/ventral/pattern/accent/keratin (HSV-derived) + roughness, fur |
| `Pattern` | Gray-Scott f/k, mode (RD/Voronoi/countershading), strength, frequency scale, Murray coupling |
| `BakedMaps` | baked albedo/normal/material maps |
| `Gait` / `Pose` | phases, stride, wave/breath params; per-frame joint positions |

## 7. Mapping to this library (implementation notes)

- `procedural/creaturegen.hpp` implements §1–§5 as pure CPU functions on top of G24
  (`Noise`), G25 (`sampleField`/`marchingCubes`), G29 (`sdf::smoothMin`) and the G30
  `Skeleton` type; deterministic per seed, no GL required. §4.3–§4.6 are
  `biomeInfo()` / `derivePalette()` / `derivePattern()` feeding `bakeMaterial()`.
- Unit tests (`tests/test_procedural_creaturegen.cpp`): allometry monotonicity, bilateral
  symmetry of the generated skeleton, SDF sign inside/outside + determinism, mesh validity
  + unit normals + keratin mask, Turing pattern range/determinism, countershading
  (dorsal darker than ventral), two-bone IK reachability, gait determinism + feet on
  terrain.
- Demo: `examples/creature_showcase` renders three different G32 creatures (horned herbivore,
  frontal-eyed carnivore, striped serpentine) side by side on procedural Corinthian columns in
  a pitch-dark hall lit only by flickering torch point lights with G35 flame particles —
  headless to PNG (`docs/images/ci/g32_creature_showcase_wide.png`,
  `..._closeup.png`, rendered by the CI docs-screenshots job).
